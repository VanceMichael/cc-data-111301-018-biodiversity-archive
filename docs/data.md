# 来源资料约定

来源采用 Darwin Core 文本资料包，meta.xml 为列与文件描述。读取规则（文件位置、
编码、分隔符、引号、忽略行数、默认值）全部来自 meta.xml，不按固定英文表头解析。

## 三种键不可混用

* core 的 `id`：资料包内部的本地关联键，只在同一发布内标识核心行；
* 对外 `occurrenceID`：核心行里的业务术语，用于跨发布识别同一次观察；
* extension 的 `coreid`：只在同一发布内指向某条核心行的本地键。

重复本地行号只在对应数据集与发布内有意义，因此仓储里所有行身份都带
`(数据集, 发布摘要)` 限定，不同保护地同样的本地键 `1` 不会互相串数据。

## 解析约定

* 同一术语出现多列时保留全部取值（有序列表），转字典不会互相覆盖；
* meta.xml 未描述的列以 `urn:biodiversity-archive:unknown-column#列号` 保留；
* 无 `index` 的默认值字段对每行生效；空单元格才套用默认值；
* 每张表可由多个文件组成，表内序号连续，同时保留来源文件名与物理行号
  （引号内换行不会错算行号）；
* 观察与图片资料为一对多：观察按核心行计数，图片再挂在观察下，不重复计数；
* 照片只登记资料地址与授权，不下载、不访问任何网络地址。

## 数据质量问题

问题保留而不是通过内连接掩盖：

* `core_key_missing`：核心行没有 id 本地键；
* `duplicate_core_key`：同一发布内核心本地键重复，两行都保留；
* `duplicate_occurrence_id`：同一发布内对外 occurrenceID 重复；
* `orphan_extension`：扩展行 coreid 指向不存在的核心行（缺父记录的孤立资料）。

archive-2 含一条不存在核心键的图片，作为合作方回传资料中的孤立引用保留，
可通过 `orphans` 与 `issues` 查询。所有图片地址均为 example.invalid，
不进行网络读取。

## 接收与对比

* 发布以 `(数据集, SHA-256)` 为身份，同一数据集内重复接收幂等；
* 新发布只替换该数据集的当前指针，历史发布与其他数据集都不消失；
* 扩展为空不会删除核心观察；
* `diff` 区分观察本身的增删改与附属图片资料的增减，并给出 `is_media_only`
  判断，便于说明纠正后的资料包变化的是观察还是它的附属资料。
